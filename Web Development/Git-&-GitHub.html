📖 What is Git?

Git is a distributed version control system used to track changes in source code during software development. It allows developers to save project history, collaborate with team members, experiment with new features safely, and restore previous versions whenever required. Unlike traditional file backups, Git stores snapshots of your project efficiently and keeps a complete history of every change.


Think of Git as a time machine for your code. Every time you save your work using Git, it creates a checkpoint called a commit. If something breaks later, you can simply go back to an earlier commit instead of rewriting everything.

🚀 Why Git Matters

  • Tracks every change made in a project.
  • Allows multiple developers to work together without overwriting each other's work.
  • Makes collaboration easier through platforms like GitHub.
  • Provides complete version history of the project.
  • Allows developers to experiment using branches without affecting the main project.
  • Enables quick recovery if files are deleted or code breaks.
  • Industry standard tool used by almost every software company.

💡 Imagine This...

Imagine you are writing your semester project report. Version 1 → First Draft Version 2 → Added Images Version 3 → Corrected Errors Version 4 → Final Submission Now imagine Version 4 gets corrupted. Without Git, you may lose everything. With Git, you simply return to Version 3 in seconds. That's exactly what Git does for software developers.

⚙️ Installing Git

Before using Git, you need to install it on your computer. Git is available for Windows, macOS, and Linux. After installation, you can access Git using the command line (Terminal or Command Prompt).

  1. Download Git from the official website.
  2. Install it using the default settings.
  3. Open Terminal (macOS/Linux) or Git Bash (Windows).
  4. Verify the installation by running the following command:

git --version

If Git is installed successfully, it will display the installed version number.

🛠️ Configure Git

Before making your first commit, Git needs your name and email address. These details are stored inside every commit and help identify the author. 


git config --global user.name "Your Name"

git config --global user.email "you@example.com"

To check your configuration, use: 


git config --list

📌 Essential Git Commands

Command Description
git init Creates a new Git repository.
git status Shows the current status of files.
git add . Adds all modified files to the staging area.
git commit -m "message" Saves changes permanently.
git log Displays commit history.
git branch Lists available branches.
git checkout branch-name Switches to another branch.
git merge branch-name Merges another branch into the current branch.
git push Uploads commits to GitHub.
git pull Downloads the latest changes from GitHub.
git clone URL Copies an existing repository to your computer.

🧩 Basic Git Workflow


git init

git add .

git commit -m "Initial Commit"

git branch -M main

git remote add origin https://github.com/username/repository.git

git push -u origin main

This is the most common workflow followed by developers when creating and uploading a project to GitHub for the first time.

💻 Real Example

Suppose you created a website named Portfolio Website. After finishing your work, you want to upload it to GitHub. 


git init

git add .

git commit -m "Created Portfolio Website"

git push origin main

Now your project becomes available on GitHub, making it easy to share, collaborate, and maintain version history.

🌿 Git Branches

A branch is an independent line of development in Git. It allows developers to work on new features or bug fixes without affecting the main project. Once the work is complete, the branch can be merged back into the main branch.

Common Branch Commands


# View all branches
git branch

# Create a new branch
git branch feature-login

# Switch to a branch
git checkout feature-login

# Create and switch in one command
git checkout -b feature-login

# Switch back to main
git checkout main

Using branches keeps your code organized and prevents unfinished work from affecting the stable version of the project.

🔀 Merging Branches

After completing your work in a branch, you can combine it with the main branch using the merge command. 


git checkout main

git merge feature-login

Git automatically combines changes whenever possible. If the same lines are edited in both branches, Git creates a merge conflict, which must be resolved manually.

📤 GitHub Pull Requests

A Pull Request (PR) is a request to merge your changes into another branch. It allows teammates to review your code, suggest improvements, and approve the changes before they become part of the main project.

Typical Pull Request Workflow

  1. Create a new branch.
  2. Make changes to your code.
  3. Commit the changes.
  4. Push the branch to GitHub.
  5. Create a Pull Request.
  6. Team members review the code.
  7. Merge the Pull Request.

Pull Requests improve code quality by introducing code reviews before merging.

🍴 What is Forking?

A fork is your own copy of someone else's GitHub repository. It allows you to experiment, contribute to open-source projects, and make changes without affecting the original repository.

After making changes in your fork, you can create a Pull Request to propose your updates to the original repository.

⚠️ Common Mistakes Beginners Make

  • Not committing frequently: Small, meaningful commits make it easier to track changes and debug issues.
  • Writing poor commit messages: Avoid messages like Update or Changes. Instead, write descriptive messages such as Add login authentication.
  • Working directly on the main branch: Always create a separate branch for new features or bug fixes.
  • Ignoring git status: Check the repository status before staging or committing files.
  • Forgetting to pull before pushing: Always pull the latest changes to avoid merge conflicts.
  • Uploading sensitive information: Never commit passwords, API keys, or confidential data to a public repository.

💡 Best Practices

  • Commit your work regularly.
  • Write meaningful commit messages.
  • Keep commits small and focused.
  • Use branches for every new feature.
  • Pull the latest changes before starting work.
  • Review your code before creating a Pull Request.
  • Use a .gitignore file to exclude unnecessary files.
  • Backup your projects on GitHub.
