CSS Transitions

Smooth out state changes across UI pseudo-classes and classes with lightweight CSS transitions.

Why This Matters

Abrupt, instantaneous state switches can feel jarring and cheapen the user experience. When a user hovers over a card, focuses a text input, or clicks a dropdown, an animated transition eases the change, making your interface feel responsive and polished.

Transitions differ from keyframe animations in that they need an explicit trigger (like :hover, :focus, or an added JavaScript class) to interpolate smoothly between an initial state and a target state.

Concept

Transitions consist of four foundational properties:

  • transition-property: Specifies which CSS properties should transition (e.g., background-color, transform). Avoid using all in production for better performance.
  • transition-duration: Time interval over which the transition occurs (e.g., 200ms, 0.3s). Snappy UI micro-interactions usually sit between 150ms and 300ms.
  • transition-timing-function: Mathematical curve controlling acceleration (ease, linear, ease-out, or custom cubic-bezier).
  • transition-delay: Waiting period before the transition starts after the trigger fires.

Syntax

/* Good Practice: Declare the transition on the BASE rule */
.interactive-card {
    background-color: #1e293b;
    transform: translateY(0);
    box-shadow: 0 4px 6px -1px rgba(0, 0, 0, 0.1);

    /* property | duration | timing-function | delay */
    transition: transform 0.25s cubic-bezier(0.16, 1, 0.3, 1),
                box-shadow 0.25s ease-out,
                background-color 0.2s linear;
}

/* Hover state triggers interpolation */
.interactive-card:hover {
    background-color: #334155;
    transform: translateY(-6px);
    box-shadow: 0 20px 25px -5px rgba(0, 0, 0, 0.3);
}
