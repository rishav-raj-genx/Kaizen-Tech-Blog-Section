Concept

CSS Selectors match HTML elements on the page and apply visual styles to them, using specificity scores to resolve conflicts when multiple rules target the same element.

CSS 
/* Element, Class, and State Pseudo-Class */
button.primary-btn:hover {
  background-color: #0284c7;
  transform: translateY(-2px);
}

Why This Matters

Without understanding specificity, styling issues often lead to overuse of !important tags, creating hard-to-debug overrides across the codebase. Mastering selectors lets you target elements precisely without adding redundant classes or breaking the cascade.

Selector Types

  • Universal: * targets all elements across the DOM.
  • Type: Targets elements by their HTML tag name (e.g., h1, p).
  • Class: Targets elements by class name (e.g., .card).
  • ID: Targets an element by its unique identifier (e.g., #navbar).
  • Attribute: Matches attributes and their values (e.g., [type="checkbox"]).

The Specificity Scale

DIAGRAM 
Specificity Hierarchy: (Inline, ID, Class, Type)

Selector                        | ( a , b , c , d ) | Points
--------------------------------+-------------------+-------
style="color: red;"             | ( 1 , 0 , 0 , 0 ) | 1000
#primary-header                 | ( 0 , 1 , 0 , 0 ) |  100
.nav-bar .item.active           | ( 0 , 0 , 2 , 0 ) |   20
header nav a:hover              | ( 0 , 0 , 1 , 2 ) |   12
div p                           | ( 0 , 0 , 0 , 2 ) |    2

* 1 ID will always override 100 stacked classes!

Syntax & Combinators

Combinators define relationships between target selectors:

CSS 
/* Descendant selector: any p inside article */
article p { color: #334155; }

/* Child selector: direct children only */
ul > li { list-style: square; }

/* Adjacent sibling: immediate next sibling */
h2 + p { font-weight: 600; }

/* General sibling: any following sibling */
h2 ~ p { font-size: 0.95rem; }

Pseudo-Classes & Elements

Pseudo-classes select state, while pseudo-elements target sub-parts of an element:

CSS 
/* Pseudo-classes (State) */
input:focus { border-color: #0284c7; }
li:nth-child(even) { background: #f8fafc; }

/* Pseudo-elements (Virtual DOM hooks) */
p::first-line { font-weight: bold; }
.card::before { content: ""; display: block; }

Common Mistakes

  • Using IDs as styling selectors in CSS, which creates unnecessarily high specificity scores.
  • Over-qualifying selectors (e.g., div.container ul.nav li.item a.link) instead of using a single clean class name (.nav-link).
  • Relying on !important to fix conflicts caused by selector specificity issues.

Interview Questions

Q: What does the :is() and :where() pseudo-class do, and how do they differ?

Both allow grouping multiple selectors together. :is() takes the specificity of its highest-ranked argument, whereas :where() always has a specificity score of zero.

Quick Revision

Favor flat, single-class selectors (like BEM) to keep specificity low and predictable. Avoid styling by ID, and use combinators (>, +) only when defining parent-child relationships.

Practice Problems

  1. Calculate the specificity score of: body.dark #main-nav ul > li a:hover.
  2. Refactor a stylesheet with high specificity down to single reusable class selectors.
