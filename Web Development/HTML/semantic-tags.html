Concept

Semantic elements describe the job of a region. A browser, search engine, screen reader, and teammate can understand more from <nav> than from an unnamed <div>.

HTML 
<header>
  <nav>
    <a href="/">Home</a>
    <a href="/docs">Docs</a>
  </nav>
</header>
<main>
  <article>
    <section>...</section>
  </article>
  <aside>...</aside>
</main>
<footer>...</footer>

Why This Matters

Imagine a documentation page with ten anonymous containers. A screen reader user has to guess where navigation ends and the article begins. Semantic landmarks make that structure explicit and make maintenance easier.

Core Tags

HTML5 provides targeted containers for every major landmark:

  • <header>: Top branding, intro, or navigational bar.
  • <nav>: Primary navigation links.
  • <main>: Central topic of the document (only one per page).
  • <article>: Self-contained, syndicatable content.
  • <section>: Thematic group with its own heading.
  • <aside>: Tangential content or sidebar notes.
  • <footer>: Copyright, author information, and site links.

Visual Structure

A standard semantic page layout arranges landmarks cleanly:

DIAGRAM 
header  →  nav  →  main [article → section]  →  aside  →  footer

+-------------------------------------------------------------+
|                           <header>                          |
|  +-------------------------------------------------------+  |
|  |                         <nav>                         |  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
|  <main>                                      |  <aside>     |
|  +----------------------------------------+  |              |
|  |               <article>                |  | Related      |
|  |  +----------------------------------+  |  | Links        |
|  |  |            <section>             |  |  |              |
|  |  +----------------------------------+  |  |              |
|  +----------------------------------------+  |              |
+-------------------------------------------------------------+
|                           <footer>                          |
+-------------------------------------------------------------+

Syntax

Implement proper nesting of semantic elements:

HTML 
<article class="blog-post">
  <header>
    <h1>Understanding Semantic Tags</h1>
    <p>Published on September 8, 2026</p>
  </header>
  <section>
    <h2>Introduction</h2>
    <p>Semantic markup forms the backbone of web accessibility.</p>
  </section>
</article>

Examples

Comparing non-semantic vs. semantic implementations:

Non-semantic (Anti-pattern):

<div class="header"><div class="nav">...</div></div>

Semantic (Standard):

<header><nav><ul><li><a href="...">...</a></li></ul></nav></header>

Common Mistakes

  • Using multiple <main> tags on a single page without the hidden attribute.
  • Wrapping every single element in <section> instead of using generic <div> for purely visual styling wrappers.
  • Using <aside> inside an article for content that is not relevant to that article.

Interview Questions

Q: What is the difference between <article> and <section>?

An <article> represents self-contained content that could be distributed independently (e.g., in an RSS feed). A <section> represents a thematic grouping of content, typically with a heading.

Quick Revision

Always build from content meaning outward. Use <header>, <nav>, <main>, <article>, <section>, <aside>, and <footer> to create accessible landmarks before styling with CSS.

Practice Problems

  1. Refactor a classic "div soup" dashboard template into a semantic structure.
  2. Audit a news article page with a screen reader to verify navigation jumps work across landmarks.
