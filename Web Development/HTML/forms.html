Why This Matters

Every checkout flow, search bar, login screen, and comment box relies on HTML forms. Poorly written forms break browser password managers, destroy accessibility for keyboard-only users, and lead to high abandonment rates on checkout flows.

Using native HTML attributes like required, type="email", and explicit <label for="..."> tags provides out-of-the-box mobile keyboards (showing numeric or email keys automatically) and prevents unnecessary JavaScript bloat.

Concept

An HTML form coordinates user inputs and packages them into HTTP requests:

  • The <form> Container: Configured using action (target URL) and method (usually GET for searches or POST for sensitive/state-altering payloads).
  • Accessible Labels (<label>): Directly tied to input elements via the for attribute matching the input's id.
  • Native Input Types: Types like email, password, number, date, and tel ensure native OS keyboards adapt automatically.
  • Constraint Validation: Attributes like required, pattern, minlength, and maxlength intercept bad data before it reaches your backend server.

Syntax

<form action="/api/register" method="POST" class="auth-form">
    <!-- Name Field -->
    <div class="form-group">
        <label for="username">Full Name</label>
        <input type="text" id="username" name="username" required minlength="3" autocomplete="name">
    </div>

    <!-- Email Field -->
    <div class="form-group">
        <label for="user-email">Email Address</label>
        <input type="email" id="user-email" name="email" required autocomplete="email">
    </div>

    <!-- Password Field with Pattern -->
    <div class="form-group">
        <label for="password">Password (min 8 characters)</label>
        <input type="password" id="password" name="password" minlength="8" required>
    </div>

    <button type="submit">Create Account</button>
</form>
