What is BSON

BSON stands for Binary JSON. It is the format MongoDB uses to store data internally. Even though developers write data in a JSON-like format, MongoDB converts it into BSON before saving it in the database.

Think of BSON as an upgraded version of JSON. It stores data in binary format, which makes it easier and faster for MongoDB to process large amounts of data.

Why it matters

BSON is used to overcome JSON's limitations by providing better data type support and improved performance for machine processing.

  • Addresses limitations of JSON.
  • Supports advanced data types (ObjectId, Date, Binary).
  • Encodes data more precisely.
  • Enables efficient storage and fast query performance.
  • Used by MongoDB as its primary data format.
  • Suitable for applications requiring a robust and efficient data format.

Syntax

When inserting data into MongoDB, you use JSON-like syntax.

db.students.insertOne({
    name:"Rituraj",
    age:19,
    course:"B.Tech AI"
});

Although this looks like JSON, MongoDB converts it into BSON before saving it.

Examples

Example 1: Student Document

db.students.insertOne({
    name:"Riya",
    age:20,
    city:"Delhi"
});

MongoDB automatically adds an _id field to uniquely identify the document.

Example 2: Date Field

db.events.insertOne({
    event:"Hackathon",
    date: new Date()
});

Here, the date is stored as a BSON Date type instead of a normal string.

Example 3: Array

db.students.insertOne({
    name:"Aman",
    skills: ["HTML","CSS","MongoDB"]
});

Arrays are directly supported in BSON.

Common Mistakes

Mistake 1: Thinking BSON and JSON are the same.

Correct: JSON is a text format, while BSON is a binary format used internally by MongoDB.

Mistake 2: Writing BSON manually.

Correct: Developers only write JSON-like documents. MongoDB converts them into BSON automatically.

Mistake 3: Assuming _id is just a string.

Correct: _id is an ObjectId, which is a special BSON data type.

Interview Questions

1. What is BSON?

Answer: BSON stands for Binary JSON. It is a binary-encoded serialization format used by MongoDB to store documents in collections and transmit data over network sockets.

2. Why does MongoDB use BSON?

Answer: MongoDB uses BSON because it is optimized for high performance: it enables fast parsing, supports rich data types (like ObjectId and Date), and contains length prefixes that allow MongoDB to quickly skip unneeded fields during queries.

3. What is the difference between JSON and BSON?

Answer: JSON is a human-readable text format supporting basic types (String, Number, Boolean, Array, Object), while BSON is a machine-optimized binary format supporting additional types (ObjectId, Date, Decimal128, Binary) built for speed and efficient database operations.

4. Name some BSON data types.

Answer: Common BSON data types include ObjectId, String, Int32, Int64, Double, Decimal128, Boolean, Date, Array, Embedded Document, and Null.

5. Does MongoDB store JSON or BSON?

Answer: MongoDB stores data on disk and in memory as BSON. However, it displays documents as JSON in shells, drivers, and UI tools for developer convenience.
