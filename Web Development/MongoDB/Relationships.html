What are Relationships

Relationships in MongoDB describe how different pieces of data are connected.

Just like in real life, different things are related to each other.

For example:

  • A Student belongs to a College.
  • A Customer places many Orders.
  • An Employee works in a Department.

MongoDB stores these relationships in two main ways:

  1. Embedded Documents
  2. Referenced Documents

Think of it like this:

Imagine a school notebook.

  • If you write a student's details and marks on the same page, it is Embedding.
  • If you write student details on one page and marks on another page and connect them using the roll number, it is Referencing.

MongoDB lets developers choose whichever method is best for their application.

Figure: One-to-One (Embed) vs One-to-Many (Reference) Relationships.

Why it matters

Relationships are important because they help organize related data efficiently.

Some reasons why relationships matter are:

  • They reduce duplicate data.
  • They improve database organization.
  • They make applications easier to manage.
  • They improve query performance when used correctly.
  • They support real-world data structures like users, products, and orders.

Without relationships, managing connected data becomes difficult.

Types of Relationships

1. Embedded Relationships

Related data is stored inside a single document.

Best for data that is always accessed together.

Example:

{
    name:"Rituraj",
    course:"B.Tech AI",
    address: {
        city:"Ghaziabad",
        state:"Uttar Pradesh"
    }
}

Advantages

  • Faster reads
  • Single query
  • Easy to manage

Disadvantages

  • Larger document size
  • Difficult to update shared data

2. Referenced Relationships

Related data is stored in different collections.

Documents are connected using ObjectId.

Example

Student Collection

{
    _id:ObjectId("101"),
    name:"Rituraj",
    departmentId:ObjectId("501")
}

Department Collection

{
    _id:ObjectId("501"),
    department:"Computer Science"
}

Advantages

  • Less data duplication
  • Easier updates
  • Better for large applications

Disadvantages

  • Requires multiple queries or $lookup

Syntax

Embedded Document

db.students.insertOne({
    name:"Rituraj",
    course:"B.Tech AI",
    address: {
        city:"Ghaziabad",
        state:"UP"
    }
});

Referenced Document

db.students.insertOne({
    name:"Rituraj",
    departmentId:ObjectId("64ab123456789")
});

Using $lookup

db.students.aggregate([
    {
        $lookup:{
            from:"departments",
            localField:"departmentId",
            foreignField:"_id",
            as:"departmentInfo"
        }
    }
]);

Examples

Example 1: Embedded Relationship

db.students.insertOne({
    name:"Aman",
    address:{
        city:"Delhi",
        state:"Delhi"
    }
});

Everything is stored inside one document.

Example 2: Referenced Relationship

Student Collection

{name:"Riya",courseId:ObjectId("5001")}

Course Collection

{_id:ObjectId("5001"),course:"B.Tech AI"}

Both collections are connected using ObjectId.

Example 3: One-to-Many Relationship

{customer:"Rahul",orders:["Laptop","Mouse","Keyboard"]}

One customer has many orders.

Example 4: Many-to-Many Relationship

Student Collection

{name:"Rituraj",courses:[ObjectId("101"),ObjectId("102")]}

Course Collection

{name:"MongoDB"}

A student can enroll in multiple courses, and a course can have multiple students.

Common Mistakes

Mistake 1: Embedding Too Much Data

Wrong

Embedding very large data inside one document.

Correct

Embed only frequently accessed related data.

Mistake 2: Referencing Everything

Wrong

Using references for even small related data.

Correct

Use embedding when data is always accessed together.

Mistake 3: Forgetting ObjectId

Wrong

departmentId:"501"

Correct

departmentId:ObjectId("501")

Always use ObjectId for references.

Interview Questions

1. What are relationships in MongoDB?

Answer: Relationships in MongoDB define how different entities and data models are connected to each other (e.g. Students to Courses, Customers to Orders).

2. What are the two types of relationships in MongoDB?

Answer: The two primary ways to represent data relationships in MongoDB are:
1. Embedded Documents (Denormalized Data)
2. Referenced Documents (Normalized Data)

3. What is embedding in MongoDB?

Answer: Embedding (or denormalization) is storing related data as nested sub-documents or arrays directly within a single parent document. It allows fetching all related data in a single read operation without joins.

4. What is referencing in MongoDB?

Answer: Referencing (or normalization) is storing related data in separate collections and linking documents using reference IDs (usually ObjectId). Data is joined dynamically using $lookup during queries.

5. When should you use embedding over referencing?

Answer: Use embedding when:
• Data has 1-to-1 or 1-to-few relationships.
• Related data is frequently read together.
• The nested data size is bounded and won't exceed the 16MB document limit.

6. When should you use referencing over embedding?

Answer: Use referencing when:
• Data has 1-to-Many or Many-to-Many relationships that grow independently or infinitely.
• Data is shared and updated frequently across multiple entities.
• Embedded documents would exceed the 16MB limit.

7. Which aggregation stage is used to join collections in MongoDB?

Answer: The $lookup aggregation pipeline stage performs a left outer join between collections, pulling in documents from a referenced collection based on matching key fields.
