What is a Collection

A Collection in MongoDB is a group of related documents. It is similar to a table in a relational database, but unlike SQL tables, a collection does not require a fixed schema. This means different documents in the same collection can have different fields.

Think of a collection as a folder that stores multiple documents of the same type.

OR

A Collection in MongoDB is a group of related documents. It is used to organize and store similar types of data in one place.

For example, if you're building a college management system, you can create different collections such as:

  • Students → Stores student details
  • Teachers → Stores teacher information
  • Courses → Stores course details

Figure: Collections are containers for MongoDB documents inside a database.

Why it matters

Collections are important because they help organize data efficiently.

Some reasons why collections matter are:

  • They group related documents together.
  • They do not require a fixed schema.
  • They allow applications to evolve without changing the database structure.
  • They improve data organization and management.
  • They support indexing for faster searching.
  • They make MongoDB suitable for dynamic applications.

Without collections, storing and managing documents would become difficult.

Syntax

A collection is created automatically when you insert the first document.

db.students.insertOne({
    name:"Rituraj",
    age:19,
    course:"B.Tech AI"
});

You can also create one manually.

db.createCollection("students")

Examples

Example 1: Creating a Collection

db.createCollection("employees")

This creates a new collection named employees.

Example 2: Inserting Documents

db.students.insertOne({
    name:"Riya",
    age:20,
    city:"Delhi"
});

If the students collection does not exist, MongoDB creates it automatically.

Example 3: Multiple Documents in One Collection

db.students.insertMany([
{
    name:"Rituraj",
    age:19
},
{
    name:"Aman",
    course:"BCA"
},
{
    name:"Priya",
    city:"Lucknow"
}
]);

All three documents are stored in the same students collection, even though they have different fields.

Common Mistakes

Mistake 1: Thinking Collections Require a Fixed Schema

Wrong: Every document must have the same fields.

Correct: Documents in a collection can have different structures.

Mistake 2: Creating Too Many Collections

Wrong: Creating a separate collection for every user.

Correct: Store similar documents in one collection whenever possible.

Mistake 3: Assuming Collections Must Be Created First

Wrong: You must create a collection before inserting data.

Correct: MongoDB automatically creates a collection when the first document is inserted.

Interview Questions

1. What is a Collection in MongoDB?

Answer: A Collection is a group of related BSON documents stored together inside a MongoDB database. It serves as the primary organizational container for documents of a similar domain (e.g., students, orders).

2. Is a Collection similar to a SQL Table?

Answer: Yes, a collection in MongoDB is conceptually equivalent to a table in a relational database (SQL). However, unlike SQL tables that enforce strict column structures and data types across all rows, MongoDB collections are schema-flexible, allowing documents within the same collection to have different fields.

3. Can documents inside the same collection have different fields?

Answer: Yes. Because MongoDB is schema-flexible (NoSQL), documents in the same collection do not need to share the exact same fields or structure. One document can have 3 fields while another has 10 fields.

4. How is a Collection created in MongoDB?

Answer: A collection can be created in two ways:
1. Implicitly (Automatic): Created automatically when you insert the first document using commands like db.collectionName.insertOne().
2. Explicitly (Manual): Created manually using db.createCollection("collectionName", { options }) to specify options like capped collection sizes or validation rules.

5. Can a collection contain millions of documents?

Answer: Yes. MongoDB collections are engineered to scale horizontally and vertically, holding millions or billions of documents efficiently when indexed properly.
